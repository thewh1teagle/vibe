## Improved

- 🔍 **Les erreurs disent maintenant ce que le moteur a affiché** — quand Sona meurt en pleine transcription, la boîte de dialogue d'erreur, les journaux et le rapport de bug contiennent désormais ses dernières lignes au lieu d'un simple « failed to read sona event line », si bien que des problèmes comme celui ci-dessus sont identifiables à partir d'un rapport

## Fixed

- 🛠️ **La transcription fonctionne à nouveau sur les anciens pilotes graphiques AMD** — depuis le passage au nouveau moteur, les machines avec un pilote AMD datant de 2020 (Vulkan 1.2, courant sur les ordinateurs portables Ryzen avec graphiques Radeon) plantaient dès la première soumission GPU avec « vkQueueSubmit: Invalid queue ». Le pilote renvoie un handle de file vide depuis `vkGetDeviceQueue2` ; Sona 0.6.4 se rabat sur `vkGetDeviceQueue` et le GPU fonctionne à nouveau. Mettre à jour le pilote AMD reste une bonne idée, mais ce n'est plus nécessaire
- 🖥️ **Les anciens CPU Intel et AMD sont de retour** — Vibe ne refuse plus de transcrire sur un CPU sans AVX2. Sona embarque son moteur CPU en deux versions, une version AVX2 et une version de base AVX, et choisit celle que votre processeur peut exécuter au démarrage. Toute machine x86-64 datant de 2011 ou après transcrit désormais ; le message « Your CPU is not supported » a disparu
- 🎮 **Une mémoire GPU insuffisante n'interrompt plus l'exécution** — quand la carte graphique manque de mémoire en cours de fichier, Vibe recharge le modèle sur le CPU, retente ce fichier une fois, et termine le reste de la file sur le CPU. Ce modèle est ensuite retenu comme trop grand pour votre GPU et se charge sur le CPU à partir de là. Merci à @mikemikimike pour le signalement et le premier correctif (#1471, #1472)
