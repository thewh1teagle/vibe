## Improved

- 🔍 **오류가 이제 엔진이 출력한 내용을 보여줌** — Sona가 트랜스크립션 도중 죽으면, 오류 대화상자와 로그, 버그 리포트에 단순한 "failed to read sona event line" 대신 엔진의 마지막 출력이 담기므로, 위와 같은 문제를 리포트만으로 파악할 수 있습니다

## Fixed

- 🛠️ **구형 AMD 그래픽 드라이버에서 트랜스크립션이 다시 됩니다** — 새 엔진으로 전환한 이후, 2020년대 AMD 드라이버(Vulkan 1.2, Radeon 그래픽을 탑재한 Ryzen 노트북에서 흔함)를 사용하는 기기는 첫 GPU 제출에서 "vkQueueSubmit: Invalid queue" 오류로 크래시했습니다. 드라이버가 `vkGetDeviceQueue2`에서 빈 큐 핸들을 반환하는 문제로, Sona 0.6.4는 `vkGetDeviceQueue`로 대체하여 GPU가 다시 작동합니다. AMD 드라이버를 업데이트하는 것은 여전히 좋은 방법이지만 더 이상 필수는 아닙니다
- 🖥️ **구형 Intel 및 AMD CPU가 다시 지원됩니다** — Vibe는 이제 AVX2가 없는 CPU에서도 트랜스크립션을 거부하지 않습니다. Sona는 CPU 엔진을 AVX2 빌드와 AVX baseline 빌드 두 가지로 제공하며, 시작 시 프로세서가 실행할 수 있는 쪽을 선택합니다. 2011년 이후의 모든 x86-64 기기가 이제 트랜스크립션할 수 있으며, "Your CPU is not supported" 메시지는 사라졌습니다
- 🎮 **GPU 메모리 부족이 더 이상 실행을 중단시키지 않음** — 파일 처리 도중 그래픽 카드의 메모리가 부족해지면, Vibe는 모델을 CPU에서 다시 로드하고 해당 파일을 한 번 재시도한 뒤 나머지 대기열을 CPU에서 마칩니다. 해당 모델은 이 GPU에 너무 크다고 기억되어 이후로는 CPU에서 로드됩니다. 제보와 초기 수정을 제공해 준 @mikemikimike에게 감사드립니다 (#1471, #1472)
