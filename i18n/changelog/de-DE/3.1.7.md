## New

- 🗣️ **Benennen Sie Ihre Sprecher** — klicken Sie auf ein "Speaker 1"-Label in einem fertigen Transkript und tippen Sie einen Namen ein. Er ersetzt das Label auf jeder Zeile dieses Sprechers, am Bildschirm und in jedem Export (Text, Markdown, HTML, SRT, VTT, PDF, DOCX; JSON behält den Index und ergänzt `speakerName`). Namen werden mit dem Projekt gespeichert, sodass sie beim erneuten Öffnen wieder da sind
- 🎯 **Eine Zeile dem richtigen Sprecher zuordnen** — dasselbe Popover verschiebt eine Zeile zu einem anderen Sprecher oder zu einem neuen. Eine kurze Zeile, die die Sprechererkennung ganz ohne Sprecher gelassen hat, zeigt jetzt einen gestrichelten Platzhalter, damit ihr einer zugewiesen werden kann. Sona 0.6.2 ordnet solche Zeilen außerdem dem nächstgelegenen Sprecherwechsel innerhalb von 1,5 Sekunden zu, sodass von vornherein deutlich weniger ohne Label ankommen
- 🔗 **Mehrere Links auf einmal transkribieren** — fügen Sie eine ganze Reihe Links in das Link-Feld ein, oder fügen Sie sie einzeln mit dem Plus-Button hinzu, und sie reihen sich darunter in einer Liste ein. Sie werden nacheinander heruntergeladen; ein fehlgeschlagener wird übersprungen und am Ende aufgelistet, der Rest geht direkt in die Transkription. Das Feld leert sich, sobald der Lauf beginnt

## Fixed

- 🦜 **Ein Whisper-Prompt blockiert Parakeet oder Nemotron nicht mehr** — diese Engines nehmen keinen Prompt entgegen, und ein gespeicherter ließ jeden Lauf mit "does not support text prompts" fehlschlagen. Der Prompt wird jetzt aus der Anfrage weggelassen, wenn das geladene Modell meldet, dass es ihn nicht verwenden kann (ebenso den Übersetzen-Schalter), sodass er gespeichert bleibt, für den Fall, dass Sie zu Whisper zurückwechseln. Das Prompt-Feld in den Einstellungen weist darauf hin, wenn das gewählte Modell es ignoriert
- 🪟 **Links mit nicht-lateinischen Titeln schlagen unter Windows nicht mehr fehl** — yt-dlp kann Bytes ausgeben, die nicht UTF-8 sind, und das Lesen seiner Ausgabe brach den gesamten Download beim ersten davon ab. Dank an @mikemikimike (#1473)
